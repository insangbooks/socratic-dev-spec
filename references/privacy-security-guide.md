# 개인정보·보안·학교 환경 확인
교육용 프로그램일 가능성이 있으므로 관련이 있을 때 다음 사항을 반드시 확인한다.

- 학생 이름
- 학번
- 연락처
- 성적
- 출결
- 상담 기록
- 사진과 영상
- 건강 정보
- 학부모 정보
- 미성년자 개인정보
- 외부 AI 서비스로 전송되는 정보
- 학교 또는 교육청의 보안 정책
- 자료 보관 기간
- 자료 삭제 방법
- 사용자별 접근 권한
- 관리자 접근 범위
- 백업과 복구
- 학교 내부망 사용 여부
- 공개 인터넷 서비스 여부

다음 원칙을 적용한다.

- 필요한 개인정보만 최소한으로 수집한다.
- 수집 목적이 분명하지 않은 정보는 저장하지 않도록 제안한다.
- 역할별로 필요한 정보만 열람하게 한다.
- 학생 개인정보를 개발용 예시나 로그에 그대로 넣지 않도록 한다.
- 실제 학생 정보 대신 가상 데이터로 시제품을 만들 수 있는지 확인한다.
- 비밀번호, API 키, 비밀값을 소스코드에 직접 작성하지 않도록 명세한다.
- 중요한 작업에는 입력 검증과 권한 확인을 요구한다.
- 개인정보가 로그, 오류 메시지 또는 URL에 노출되지 않도록 고려한다.
- 외부 AI 서비스로 전송되는 데이터와 그 필요성을 명확히 한다.
- 자료 삭제와 계정 삭제 시 처리 방식을 정한다.
- 백업 자료의 보관 및 삭제도 고려한다.

법률, 규정 또는 기관 정책을 확정적으로 단정하지 않는다.

확인이 필요한 법적·정책적 사항은 다음과 같이 표시한다.

- 확인이 필요한 사항
- 확인해야 할 담당자 또는 기관
- 확인 전에는 사용하지 말아야 할 기능
- 개인정보를 제외하고 시제품을 만드는 대안

이 스킬은 설계 단계의 개인정보·보안 검토를 지원하지만 다음을 대체하지 않는다고 명확히 한다.

- 법률 전문가 검토
- 학교 또는 교육청의 공식 보안 승인
- 실제 소스코드 보안 감사
- 클라우드 보안 설정 점검
- 모의해킹 또는 침투 테스트

보안 요구사항은 다음 세 단계로 구분한다.

1. 개발 전에 확인할 사항
2. 개발 중 구현할 사항
3. 배포 전에 검증할 사항
## 단계별 보안 요구사항
- 개발 전: 수집 목적·최소 항목·접근 역할·보관 기간·외부 전송·기관 승인 담당자를 확인한다. 미확인 사항은 운영 전 차단 조건으로 기록한다.
- 개발 중: 저장·전송 암호화와 키 관리, 서버 측 입력 검증·객체별 권한 검사·학교/학급 간 격리, 최소 권한, 안전한 세션을 요구한다. CORS는 필요한 출처만 허용하며 인증을 대체하지 않는다. 시크릿은 서버 환경변수나 비밀 저장소에서 관리한다.
- 개발용 예시에는 실존 인물과 연결되지 않는 합성 ID와 가상 데이터만 사용한다. 가명 ID도 재식별 가능하면 개인정보로 취급한다. 로그·오류·URL·테스트 자료에 개인정보나 비밀값을 평문으로 남기지 않는다.
- 배포 전: 권한 우회·입력 오류·개인정보 노출·키 노출·CORS 설정·백업 복구·삭제 전파를 검증한다. 백업은 암호화하고 접근과 보관 만료를 제한한다.
- 외부 AI 입력은 목적·최소화·비식별화·전송 승인·보관 정책을 확인하고, 확인 전 실제 학생 자료 전송은 명세에서 보류한다.
- 외부 라이브러리 도입 시 공식 배포처, 유지관리 상태, 알려진 취약점, 라이선스, 불필요한 의존성과 버전 고정 여부를 검토한다.

## 검토 기록
항목 | 수집 목적 | 접근 역할 | 저장/전송 위치 | 보호 방식 | 보관·삭제·백업 | 확인 담당자 | 확인 전 제한
미결정 사항을 안전하다고 간주하지 않는다. 위험 발견 및 요구사항 작성이며 전문 보안 감사나 법률 검토를 대신하지 않는다.
